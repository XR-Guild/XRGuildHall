# 3D Asset Standards

Rules for every 3D asset in the Hall, whether a person or an AI assistant made it. They serve two goals:

1. **Source files stay editable** by people and AI assistants working on the same file.
2. **Exported files meet the target spec** for a browser-native build.

Part A applies to Blender source files. Part B applies to every delivered GLB, whatever tool produced it.

> **Budgets are provisional.** The minimum target device has not been chosen. The numbers in `scripts/assets/asset-spec.json` assume a standalone headset browser as the floor and will be revised once the team decides.

## Where assets come from in this repo

| Source | Where | Source of truth |
|---|---|---|
| Procedural world (Guild Hall, Library, colonnade, garden, furniture) | `guild-hall-library/src/` | The TypeScript builders. The live build creates geometry at runtime |
| Arrival.space export of that world | `guild-hall-library/src/export.ts`, run by `guild-hall-library/tools/arrival-export.mjs` | The builders plus `export.ts`. The GLBs are output, not source |
| Imported models | `guild-hall-library/public/models/` (loaded), `guild-hall-library/models-source/` (kept, not loaded) | The GLB, or the `.blend` it was cleaned up in |
| New hand-modelled assets | Blender | The `.blend` (Part A) |

For the procedural world, geometry and material fixes go into `guild-hall-library/src/`. Editing an exported GLB by hand is lost on the next export.

## Part A — Blender source files

### File layout

- One `.blend` per asset or per tightly related set (for example, one window family).
- Textures live beside the `.blend` in `textures/`, referenced with relative paths. Never pack images into the `.blend`.
- Scene units are metric, unit scale 1.0. One Blender unit is one metre.
- Every file has a text datablock named `README` (Scripting workspace → Text editor) containing:
  - what the asset is and where it goes in the Hall
  - the source of truth: `hand-edited` or `generated by <script path>`
  - anything a future editor needs to know before changing it

### Source of truth

A file is either hand-edited or generated by a script. Mixing the two silently is how edits get lost.

- **Hand-edited:** the `.blend` is the source. Scripts may add to it but must not rebuild existing objects.
- **Generated:** the script is the source. It is committed next to the `.blend`, has its parameters at the top, and produces the same file every time it runs. Manual tweaks go into the script, not the `.blend`.

To move a generated file to hand-edited, update its `README` text and stop running the script.

### Collections

- Each top-level collection is one exported asset. Its name is lowercase words joined by `-` or `_` and becomes the GLB file name (`hall-bench` → `hall-bench.glb`).
- Each top-level collection has a custom property `asset_class` set to one of the classes in the spec.
- Collision geometry goes in a child collection named `<asset>-collision`.
- Anything that is not exported (reference images, cameras, preview lights, scale figures) goes in a collection whose name ends in `-reference`.
- No objects sit loose in the scene's root collection.

### Naming

- Objects, meshes and materials have descriptive names a newcomer can understand. Readable names such as `Window 01 | gilt sill corner` are fine.
- No default names (`Cube`, `Cylinder.003`, `Material`).
- No auto-numbered suffixes (`.001`). If Blender added one, the object is either a duplicate that should be a linked duplicate, or it needs its own name.
- A mesh datablock has the same name as its object, unless several objects share it.

### Geometry

- Keep modifiers live (Mirror, Array, Bevel, Subdivision, Solidify). Do not apply them in the source file; the exporter applies them. A live modifier stack is what lets the next person change a segment count.
- Apply scale on every mesh object. Scale is `1, 1, 1`.
- Place the origin where the asset meets the world: usually the centre of its base, on the floor.
- Repeated parts are linked duplicates (`Alt+D`) or collection instances, never full copies.
- Set segment counts on curves, tubes, lathes and bevels deliberately. Ornament and trim are where triangle budgets are lost.
- Curve and text objects count against the budget at the geometry they export as, not what they look like in the file. Their resolution, bevel depth and extrusion settings all multiply triangles. A few dozen text objects can export as hundreds of thousands of triangles.
- Before exporting, check the triangle count the validator prints for each collection, and lower curve and text resolution until it fits the budget. Don't convert curves or text to meshes to hide the cost; keep them live so the resolution can still be tuned.
- Prefer quads and triangles. Avoid n-gons, which triangulate unpredictably on export.
- Weld vertices unless a hard edge is intended.

### Materials

- Use Principled BSDF with node setups the glTF exporter supports.
- Reuse materials. Two materials with the same settings are one material.
- Clearcoat, sheen, iridescence, transmission and volume each need a visible reason. Default to plain metallic-roughness.

### Before saving

- Purge orphan data (File → Clean Up → Purge Unused Data).
- Run the validator:

```bash
blender --background path/to/file.blend --python scripts/assets/validate_blend.py
```

## Part B — Exported GLB

### Export

- Format: glTF Binary (`.glb`), +Y up, modifiers applied, one file per top-level collection.
- Export custom properties so `asset_class` travels with the file.
- File names are lowercase words joined by `-` or `_`.
- Collision meshes are separate files named `<asset>-collision.glb`.
- No file exceeds 25 MB, the Arrival.space per-file limit.

### Budgets

Per asset, by class. Current values are in `scripts/assets/asset-spec.json`.

The validator takes the class from, in order: `--class`, the scene's `asset_class` custom property, a `-collision` file name, the `file_classes` map in the spec, then the default `prop`. The map covers existing exports that don't carry the property yet.

| Class | Use for | Triangles | Materials | Largest texture |
|---|---|---|---|---|
| `prop-small` | lanterns, plants, small decor | 500 | 1 | 512 |
| `prop` | benches, chairs, shelves | 2,000 | 3 | 1024 |
| `prop-hero` | one-off focal pieces | 10,000 | 4 | 1024 |
| `architecture` | hall, library, colonnade | 50,000 | 8 | 2048 |
| `collision` | collision meshes | 750 | 1 | none |

### Rules

| Rule | Why |
|---|---|
| Every mesh, material and node is named | Parts must be identifiable in the file |
| No duplicate materials | Each material is at least one draw call |
| Repeated geometry is instanced | Saves download size and draw calls |
| Textures are power-of-two | Required for mipmaps and block compression |
| Normal maps are never JPEG | Lossy compression corrupts normal data |
| Single-channel data is stored single-channel | An RGBA mask wastes three channels |
| Shared textures are not embedded in every file | The same wood texture in six files is downloaded six times |
| Delivered geometry is meshopt-compressed | Raw float geometry dominates file size |
| Delivered textures are KTX2 | JPEG and PNG expand to full RGBA in GPU memory |

### Validate and optimise

Check an export:

```bash
python3 scripts/assets/validate_glb.py path/to/asset.glb
```

Produce the delivery file:

```bash
scripts/assets/optimize_glb.sh path/to/asset.glb path/to/delivery/asset.glb
```

Check the delivery file, where compression and KTX2 are required:

```bash
python3 scripts/assets/validate_glb.py --stage delivery path/to/delivery/asset.glb
```

Pass several files at once to detect images duplicated across them. The Arrival export produces about 48 files, so run it on the whole folder.

Texture conversion needs [KTX-Software](https://github.com/KhronosGroup/KTX-Software) installed.

### Check the loader before compressing

A meshopt or KTX2 file only loads if the loader has the matching decoder. The app's `GLTFLoader` in `guild-hall-library/src/main.ts` currently registers neither, and support in Viverse and Arrival.space is unconfirmed. Until a decoder is confirmed for every place a file loads:

- don't ship compressed files to that place;
- the validator treats missing compression as a warning, not an error, even at the delivery stage.

Once confirmed, add `meshopt` or `ktx2` to `confirmed_decoders` in the spec and the validator will require it.

## Generated models from other tools

Output from generators such as Tripo is raw material. It enters the repo only after it passes Part B. In practice that means importing it into Blender, reducing and renaming it, and exporting again.

## Pending team decisions

These are decided by the team at the Monday sync and tracked as `needs-decision` issues. Asset work does not decide them. Until each is settled, follow the interim rule.

| Decision | Interim rule |
|---|---|
| Minimum target device | Use the provisional budgets in the spec as they stand. Don't edit them |
| Whether the app, Viverse and Arrival.space loaders decode meshopt and KTX2 | Deliver uncompressed files. Don't add decoders to the app or entries to `confirmed_decoders` as part of asset work |
| Where shared textures live | Keep each asset's textures beside its source. Don't create a shared texture folder or move textures between assets |
