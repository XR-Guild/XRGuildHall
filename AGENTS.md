# Instructions for AI assistants

XR Guild Hall is a volunteer-built, browser-native WebXR space. See `README.md` for the project and `CONTRIBUTING.md` for the workflow. The running app is in `guild-hall-library/`; see its `README.md`.

## 3D assets

If you're working on a `.blend`, a `.glb`, or code that builds or exports geometry, `docs/ASSET-STANDARDS.md` explains how the team makes and delivers 3D assets. The main points:

- **Edit the source, not the output.** The procedural world is built by `guild-hall-library/src/`, so geometry and material fixes belong there; changes to exported GLBs are lost on the next export. A `.blend` says in its `README` text datablock whether it's hand-edited or generated by a script. If it's generated, change the script.
- **Keep other people's work.** If someone has edited objects in a file, add to the file rather than regenerating it.
- **Run the validators on what you change**, and include what they report, with any warnings you've left and why:
  - `blender --background FILE.blend --python scripts/assets/validate_blend.py`
  - `python3 scripts/assets/validate_glb.py FILE.glb [...]`

  A lot of the current art doesn't meet the provisional budgets yet, so focus on the files you touched.
- **Budgets** live in `scripts/assets/asset-spec.json`. If an asset can't fit, raise it with the team rather than changing the numbers.
- **Compression:** ship meshopt or KTX2 files only where the loader is known to decode them.
- **Open questions**, such as the target device and compression formats, are for the team to settle at the Monday sync. The standards give an interim approach for each; if a task doesn't fit it, ask.
