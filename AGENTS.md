# Instructions for AI assistants

XR Guild Hall is a volunteer-built, browser-native WebXR space. See `README.md` for the project and `CONTRIBUTING.md` for the workflow. The running app is in `guild-hall-library/`; see its `README.md`.

## 3D assets

Before creating or editing any `.blend`, `.glb`, or code that builds or exports geometry, read `docs/ASSET-STANDARDS.md` and follow it.

Required on every asset task:

1. Find the source of truth before editing (see "Where assets come from" in the standards):
   - The procedural world is built by `guild-hall-library/src/`. Fix geometry and materials there, never in exported GLBs.
   - For a `.blend`, read its `README` text datablock first. If it says `generated by <script>`, change the script, not the file.
2. Do not rebuild or replace objects a person has edited. Add to the file; do not regenerate it.
3. Run the validators and fix every error before reporting the work as done:
   - `blender --background FILE.blend --python scripts/assets/validate_blend.py`
   - `python3 scripts/assets/validate_glb.py FILE.glb [...]`
4. Report the validator output, including warnings you chose not to fix and why.

Budgets live in `scripts/assets/asset-spec.json`. Do not change them to make an asset pass.

Do not ship meshopt- or KTX2-compressed files to a loader that hasn't been confirmed to decode them.

"Pending team decisions" in the standards are not yours to settle. Follow the interim rule for each one; if a task can't be done within it, say so and stop rather than deciding.

`AstraBlender/` is a prototype. Do not treat its files or structure as a reference.
